# Design rules, net classes, copper fills and board shape (as built)

Four founder requests are built here: configurable manufacturing parameters with profiles for different production specifications, net classes, full copper fills, and board cutouts with a flexible, sketch-based board shape on which components are placed relative to any board edge. The work started from a contract slice (types and minimal bodies) and eight parallel tasks; this note records what was built. `crates/editor-core/src/tests/board_contract.rs` still pins the invariants below.

## Invariants

- **Rules come only from a fab profile.** Sparksmith ships no estimated values (founder decision, 11 November 2026); its shipped profiles are sourced files from fabricators' published capabilities: JLCPCB and PCBWay, 2- and 4-layer each, and Standard, the strictest standard limits of several (below). A new board starts on Standard, so it always has rules. A board's rules are the profile it pins plus its overrides; a board whose profile is missing has no rules ([fab profile files](#fab-profile-files)); a fab profile is the file that holds them, the rules themselves are design rules (founder decision, 11 November 2026). The test prototype fixture (`rules/fixtures/prototype.json`, test builds only) holds the former hard-coded limits so the tests that measure against them still do: 0.2 mm copper clearance, 0.3 mm copper to board edge, 0.25 mm drill-to-copper and hole-to-hole, 0.1 mm annular ring and min drill, 0.05 mm mask expansion, 0.1 mm mask web and silk width, 0.6 mm silk text height, 0.3/0.6 mm tented vias, a 0.3 mm route width and the land-estimator margins. `the_prototype_fixture_holds_the_former_hardcoded_limits` pins this. `DesignRules::default()` holds the same values as a test fixture only (`test-fixtures`); the product's land estimators take the board's profile (`ProjectRules::land_estimators` refuses without one).
- **One typed engine.** New operations: `rules.set_fab_profile`, `rules.set_override`, `rules.clear_override`, `net_class.add`/`edit`/`delete`/`assign`/`set_patterns`/`set_clearance`, `fill.add`/`edit`/`delete`/`refill`/`store`/`store_all`, `keepout.add`/`edit`/`delete`, `board.set_rectangle`, `board.start_sketch`, `board.edit`, and (since the board sketch references design, docs/board-sketch-references.md) `layout.dimension_add`/`edit`/`delete`. New queries: `rules.effective`, `rules.fab_profiles`, `rules.preview_fab_profile`, `net_class.list`, `net_class.preview_patterns`, `board.shape` and `fill.status`. All of them come from `sparksmith_core::schemas()`, so the CLI and MCP reach them through the generic `apply` and `query`. Each command is one undo step, and a failed command leaves the document unchanged. A rules command that changes nothing is not an undo step.
- **Pre-release format.** The new `Project` fields (`rules`, `board_shape`, `part_dimensions`, `fills`, `keepouts`) are serde-defaulted and skipped when empty or default. There are no migrations.
- **Pure core.** Sketch solving runs behind host traits: `FootprintEvaluator` for footprints and `BoardShapeEvaluator` for the board. Hosts pass them as `Engine::apply_hosted(rev, op, Evaluators { footprint, board })`. The desktop app (`pcb_editor::board_shape::host_evaluator`) and the automation session both pass `sparksmith_solidcraft::board::SketchBoardEvaluator`. The user profile library lives in `sparksmith-io`.
- **Clean room.** Profile values come from fabricators' public capability pages, cited per rule with the page's URL and the date read. The shipped profiles are files in the shipped library (`library/profiles/`, [shipped library](shipped-library.md)), read at run time; no fabricator data is compiled in.

## Design rules and profiles

- **Core** (`rules.rs`, `rules/profile.rs`, `rules/formula.rs`): `ProjectRules` holds a snapshot of the chosen profile (none until one is chosen), per-project overrides, net classes, class assignments and patterns, and class-to-class clearances.
  - Values resolve in this order: profile, then override, then net class, then class pair. A `Region` source is reserved and has an explicit precedence.
  - The overrides, net classes and pairs are the project's own rule set. `ProjectRules::source` says where it comes from in the user's words ("From the KiCad project" after an import; none when it was set in the project), set with `rules.set_project_source` and shown in the Rules panel as "Project rules". The fab profile stays attached for the fab limits; the KiCad importer leaves out any KiCad limit looser than the profile's, and its report says how many ("N KiCad rules looser than the fab profile were not taken").
  - `RuleSource::describe()` names the source in messages, for example "Fine 4/4" or "net class Power".
  - `rules::apply` is atomic. It names the rule in every bounds refusal.
  - `rules.set_fab_profile` takes a profile id from `rules.fab_profiles` (the board's own, one of the user's library or a shipped one), or any valid, sourced whole profile, with `options` (option id → choice id) chosen in the same step: `{"profile": "pcbway-4-layer", "options": {"limits": "minimum"}}`. The session reads an id from the profile library before the engine runs (`Session::hosted_profile`); the engine alone reads only the board's own id and refuses another (`rules.fab_profile_unknown`, naming the ids). It refuses kept overrides that break the profile (`rules.override_conflict`).
  - `rules.fab_profiles` is compact: each profile's id, name and options with their choices and defaults, the board's own first (`board: true`, with its `chosen`), about 3 KB for the five shipped profiles instead of about 135 KB. `rules.fab_profiles {"id": …}` gives one profile in full, with its rules and sources.
  - `rules.preview_fab_profile` takes the same `profile` and `options` and lists the rule changes, the dropped overrides and the board issues that would appear or go, matched by finding identity. A switch that would be refused is still previewed and carries its `refusal`.
  - `rules.set_fab_options {"options": {"limits": "minimum"}}` chooses [manufacturing options](#manufacturing-options) of the board's profile (options not named keep their choice) and keeps the overrides; `rules.preview_fab_options` previews it as a switch is previewed. A choice that orders outer copper (`outer_copper_um`, the copper weight) sets the stackup's top and bottom foils in the same undo step, and the preview lists that stackup change. `rules.set_fab_profile` takes the choices its `options` name and carries the board's other choices over where the new profile offers the same option id and choice id; its other options take the new profile's own choice (a file's defaults), and `rules.preview_fab_profile` lists what was named, kept and set to the defaults (`chosen_choices`, `kept_choices`, `reset_choices`). `rules.effective` lists the profile's options and the board's choices (`profile.options`, `profile.chosen`).
- **Checks** read the effective rules. Two pads of one placed footprint are held to the profile's pad-to-pad clearance, not to net-class or class-pair fab spacing: the footprint fixes their spacing (a QFN's pins cannot meet a power class's clearance to its exposed pad). This footprint exception covers fab spacing only. A class-to-class clearance set as an isolation clearance (`net_class.set_clearance` with `isolation: true`) is a separation the design requires between the two classes, an isolator's two sides or a connector's high-voltage and low-voltage pins, and holds between the pads of one footprint too; its finding cites the isolation (`an_isolation_clearance_holds_inside_a_footprint_and_fab_spacing_does_not`). The checks read: copper clearance, board edge with cutouts and slots (`layout/board_edge.rs` on `Project::board()`), track width, drill size, annular ring, aspect ratio, drill to copper, hole to hole, mounting holes, courtyard clearance, the footprint mask-web and silkscreen lint, and the land estimators. The routing and via refusals do too.
  - Messages give the rule, its value and its source after "; ", for example "…; needs 0.25 mm (Fine 4/4: min mask web)". The issue title is the first clause, so it stays the same when the profile changes.
  - `layout/limits.rs` caches the resolved limits for one check run.
- **Desktop.** The Board card's Rules row opens the docked Design rules panel (`pcb_editor/rules_panel.rs`).
  - The panel has a profile picker with the profile's source and a grouped rule table (profile value, a formula marked ƒ with the formula and the value's source on hover, effective value, Reset) with live overrides. A project whose profile is missing says so and offers the library's profiles to choose.
  - A profile switch is previewed first. A refused switch shows its reason as a blocker. The switch commits as one `rules.set_fab_profile`.
  - The profile's manufacturing options are choice rows under its source. Choosing another choice opens the same review ("Change fab profile option": the rules that change and the issues that appear or go, with the option's source); Use these limits commits one `rules.set_fab_options`. A switch's review adds a Stackup group when the outer copper changes, and "Choices kept" and "Choices set to the profile's defaults" groups. Other choices of a library profile are not "Differs from the library version".
  - The panel also offers Save as profile and the user library: rename, delete, import and export.
  - Issues rows whose limit is a rule offer "Show rule".
- **Fab profile library** (`crates/io/src/rule_profiles.rs`): one `ProfileFile` (`PROFILE_FILE_FORMAT` 1) per profile, stored in `UserDirs::config/fab-profiles/`. Writes are atomic; reads are bounded (256 KiB per file, at most 256 profiles). Damaged or unsupported files are reported, never rewritten. The CLI has `fab-profile list|import|export`.

## Fab profile files

A fab profile is a versioned JSON file (`{"format": 1, "fab_profile": {…}}`, `deny_unknown_fields`); a project embeds the same profile object (`rules.profile`) as its snapshot, as library revisions are pinned, so a board reopens with exactly the rules it was checked against.

- **Source.** `source` names the `publisher` and the `date` (YYYY-MM-DD) the numbers were read, both required, with an optional `document`, `url` and `notes`. Each rule may carry its own `source` (the capability page's row); one without falls back to the profile's.
- **Fabricator.** `fabricator` names the board house whose profile it is, by the id of a fabricator record (`{"format": 1, "fabricator": {"id", "name", "website"?, "source"?}}`, one file `<id>.json` each, `rules::fabricator`). The shipped records live in the shipped library's `fabricators/` shelf, the user's in `UserDirs::config/fabricators/` (`sparksmith_io::fabricators`; a user record with a shipped id takes its place). The hierarchy fabricator → profiles is data: no fabricator is named in code, and a profile's name is only its label. Every shipped profile but Standard, which is no fabricator's, names a shipped record and every shipped record has a profile (`every_shipped_profile_names_a_shipped_fabricator`). A user profile may name one or none. Profile suggestions prefer the board's own fabricator ([what the board needs](fabrication-output.md#what-the-board-needs-of-its-fab-profile)).
- **Every rule.** `rules` sets every rule by name (`RuleKey::name`: `drill_min`, `clearance_track_board_edge`, …) as `{"value": …}` or `{"formula": "…"}`. A missing, unknown or duplicated rule is refused, never filled in. The one exception is `thermal_angle_round` (`RuleKey::optional`), the thermal spoke angle of round pads and vias: a profile written before it existed leaves it out, and then round pads and vias take `thermal_angle` like every other pad, as before. A profile or a project override that sets it makes the file list the feature `round_pad_thermal_angle`. A limit the fabricator does not publish is 0 (not checked) with a source saying so; a default that is the profile author's choice says that.
- **Formulas.** A formula is a Rhai expression of other rules (`via_drill_default + 0.15`, `silk_line_width_min / silk_text_height_min`). It runs sandboxed: an expression only, no loops, functions of its own, printing, `eval`, modules or I/O, and at most 10,000 operations. Formulas evaluate in dependency order after the values and after the project's overrides, so a formula follows an override of a rule it names; an override of the formula's own rule replaces it. A formula that names itself through any chain is refused with the chain (`rules.formula_cycle: … via_drill_default → via_diameter_default → via_drill_default`); one that names no rule, fails or gives a value of another kind is refused naming the rule.
- **Manufacturing options.** A fabricator's limits can depend on what is ordered (founder decision, 14 November 2026: "the limit depends on JLCPCB's profile; they have different limits depending on the selected manufacturing"). A profile lists `options`, each `{"id", "name", "default", "choices": [{"id", "name", "outer_copper_um"?}], "source"}`, and a rule lists `cases`, each `{"when": {"option": "choice"}, "value": …, "source": "…"}`: the first case whose every option takes its choice gives the value and its source, else the rule's own value applies. A case gives a value of the rule's kind and names only options and choices the profile offers; a profile offers at most 16 options of at most 16 choices, and a rule at most 16 cases. The profile keeps the choice of every option (`chosen`, each option's `default` until one is chosen), so a board pins its profile and its choices, and its rules are those of the choices. The rule's own value is the default choice's, so a profile reads the same without its options. The defaults are data in the profile file (founder decision C2, 14 November 2026), the same for every way a board takes a profile (a new project, `project.new`, an import); a switch keeps the board's matching choices (C3). **Copper weight is tied to the stackup** (C1): a choice may give `outer_copper_um`, the finished outer foil it orders; either every choice of an option gives it or none does, and at most one option of a profile does. The board's outer foils follow the choice (`rules.set_fab_options` and `rules.set_fab_profile` set them in the same step); a stackup edit (`layout.set_stackup`, `layout.edit_stackup`) whose top or bottom foil departs from the choice is refused (`stackup.outer_copper`), naming the option to choose instead. Refusing is the simpler of the two ways to keep them together: the copper weight has one place where it is chosen, and the stackup editor's presets (always the family's 35 µm foil) cannot change it silently. A profile without such an option leaves the stackup alone. **Mask colour follows the board** (founder decision, 20 November 2026): an option with `"follows": "mask_colour"` is chosen by the board's solder mask colour (Board › Fabrication, `layout.set_fabrication`), the one place the colour is set; each of its choices lists the colours it stands for (`"mask_colours": ["black", "white"]`, the names `layout.set_fabrication` uses), no colour twice. `layout::mask_colour` keeps the choice in the step that changes the colour or the profile (a profile switch and its preview take the board's colour; the Rules panel shows the row read-only), `rules.set_fab_options` and `rules.set_fab_profile` refuse to choose it (`rules.fab_option_follows_board`), and a file whose choice contradicts its colour, or that lists a name that is no colour, is refused. A colour no choice lists is one the fabricator does not offer: the option keeps its default and the board check reports `board.mask_colour_not_offered` (an error: "JLCPCB 2-layer does not offer a clear solder mask; it offers …"). A profile without such an option checks no colour.
- **Which boards a profile is for.** A fabricator's rows hold for some boards only: a two-layer page does not describe a four-layer board. A profile may say so: `"boards": {"copper_layers": [2], "source": "…"}`, the copper layer counts its rows cover (ascending, once each, 1–64). A board of another count gets `board.profile_layers`, an error ("JLCPCB 2-layer is for 2-layer boards; the board has 4 copper layers"). A choice may state what it needs of the board, `"requires": {"board_thickness_max_mm": 1.0, "finishes": ["enig", "osp"]}` (the finish names `layout.set_fabrication` uses; a name that is no finish refuses the file), and a chosen choice the board does not meet gets `board.fab_choice_thickness` or `board.fab_choice_finish`, errors naming the option, the choice and the board's value. The shipped profiles state their counts, and JLCPCB's 0.1 mm drilling its thickness and finish. A profile that leaves `boards` out checks no layer count. The checks are board checks, so Issues shows them, and the production check under another profile ([fabrication output](fabrication-output.md#production-check-fabricationpreflight)) evaluates them for that profile.
- **Drill files.** `drill_files` says how the fabricator reads drill files: `finished`, `drilled` with a `pth_allowance` (plated tools written at finished size plus the allowance, as Eurocircuits documents with 0.10 mm) or `not_published`. Hole sizes in Sparksmith are always finished sizes; the Excellon tool table, its comment line, the drill table and the fabrication drawing follow the setting.
- **One resolver.** `ProjectRules::effective` is the one resolution every check, tool default and output reads. A project without a profile resolves to `DesignRules::unset()` (every limit 0, no defaults); `ProjectRules::require` refuses tools and outputs that need one (`rules.no_fab_profile`): fills, sketched board outlines, the showcase. The production check blocks with an unwaivable `rules.no_fab_profile`.
- **New boards.** MCP and the stdio session's `project.new` never ask: they take `profile` (a library or shipped id, or a whole profile) and fall back to the user's default (`UserSettings::default_rule_profile`, set in Settings › Rules), else the shipped default that `library/defaults/new-project.json` names, `standard`. A default that is gone or damaged never becomes another profile silently: automation refuses the new project and names it (a session still starts, with an empty document that has no profile, so files open and `project.new` with a `profile` works), and the desktop starts the board on the shipped default and says so in a message that names the missing one. That file also names the new board's size and its stackup family and layer count (`library/stackups/`, loaded by `sparksmith_io::new_project`): the core holds none of these values. Every host starts the same way, through `sparksmith_io::new_project::engine`: the desktop's File › New and a launch without a file, the project a CLI, stdio or MCP session starts with (none when it opens a file), `project.new`, a KiCad import without `--profile`, `sparksmith parts` and `showcase`. The profile is in the document the project starts from, so no undo takes it away, and nothing asks for one; another is chosen in Board › Rules. Production says once, as information, that a check under the shipped default is no fabricator's ("Checked against Standard; choose your fabricator's profile before ordering"). **A missing profile** is left to a project file that has none (an older file, or one written by another program), and what needs rules is refused there: Route, Via, Tune and Fill when they are armed, before anything is drawn, a track's drag and Edit shape. Each opens the Design rules with the `rules.no_fab_profile` sentence above the profile picker; choosing one closes the panel again. A part dimension reads no rule and needs none: a rectangle board is solved as four lines, which no `board_outline_fit` enters (`a_rectangle_board_without_a_profile_takes_part_dimensions`). The engine refuses the same entries through CLI and MCP (routing, via, track and fill commands and their previews) with that sentence and rule, and the error's `instead` names `rules.set_fab_profile`; taking copper away needs no profile. No fill copper is computed or stored, Issues shows "No fab profile" in place of "No issues", and no card shows an unset rule as 0 mm.
- **Shipped profiles.** `library/profiles/jlcpcb-2-layer.json` and `jlcpcb-4-layer.json` are written from JLCPCB's [PCB capabilities page](https://jlcpcb.com/capabilities/pcb-capabilities), read 2026-11-11 and again 2026-11-14 (no value had changed), each rule citing its row. Their ids name no copper weight, which is an option. Both offer four options. *JLCPCB values* (default Recommended; Absolute minimum) holds the three rows that give both: "PTH annular ring" (1 oz on 2 layers: 0.25 mm recommended, 0.18 mm minimum; on 4 layers 0.20 and 0.15 mm), "PTH to Track" (0.35 mm recommended, 0.28 mm minimum; on 4 layers the minimum is the inner-layer row's 0.3 mm, since one rule covers every layer) and the via hole (C4: "② Preferred Min. Via hole size: 0.2mm" recommended, the "Min. Via hole size/diameter" 0.15 mm minimum, read 2026-11-14). It is not an order option but which of JLCPCB's two values a board is held to. Because the recommended values are the default, a board with 0.15–0.2 mm vias now gets a smallest-drill finding until it chooses Absolute minimum (or larger vias); that is intended. *Outer copper weight* (default 1 oz, 35 µm; 2 oz, 70 µm): "Finished Outer Layer Copper" offers 2.5–4.5 oz on 2 layers too, but JLCPCB publishes only their track and space, not their annular ring or mask bridge, so they are not offered. 2 oz gives track and space 0.16 mm on 2 layers ("2-layer: 0.16 / 0.16 mm") and 0.15 mm multilayer ("Multilayer: 0.15 / 0.15 mm"), applied to every copper-to-copper clearance that is narrower (pad to track has a 1 oz row only, and SMD pad to pad 0.15 mm), a PTH ring of 0.254 mm ("2 oz: 0.254 mm or above", under both value sets) and a mask bridge of 0.20 mm ("2oz: Min. pad spacing: 0.20 mm (any color)"), all read 2026-11-14. The page states weights, not thicknesses: 35 µm an ounce is the unit conversion `library/stackups/` cites. *Solder mask colour* (green, red, yellow, blue or purple: 0.10 mm bridge; black or white: 0.13 mm; 1 oz rows) follows the board's solder mask colour; the "Soldermask" row lists the colours offered ("Green, Purple, Red, Yellow, Blue, White, and Black.", read 2026-11-20). *Smallest drill* (default standard drilling; 0.1 mm for boards 1 mm or thinner with an ENIG or OSP finish, which costs more; ordered microvias win over the recommended 0.2 mm). Apart from the smallest drill, the defaults give the values the files had before they offered options. JLCPCB does not say there whether drill files are read as finished or drilled sizes, so both say `not_published`. Both ship (founder decision, 13 November 2026; `sparksmith_io::rule_profiles::shipped_profiles`, read through `ShippedLibrary`; a missing or broken file is an error naming it): the Rules picker, Settings' default, `rules.fab_profiles` and `sparksmith fab-profile list` (`"kind": "shipped"`) list them after the user's profiles, and `get`, exports and `project.new` read them by id. They are read-only: Save as fab profile… makes an editable copy. A user profile with a shipped profile's id (an import of the same file, say) takes its place everywhere; deleting it brings the shipped one back. Import other fabricators' files with `sparksmith fab-profile import FILE.json` or the panel's Import…, citing their pages.
- **PCBWay profiles.** `library/profiles/pcbway-2-layer.json` and `pcbway-4-layer.json` are written from PCBWay's [manufacturing tolerances](https://www.pcbway.com/pcb_prototype/PCB_Manufacturing_tolerances.html) and [capabilities](https://www.pcbway.com/capabilities.html) pages, read 2026-11-16, each rule citing its row. They ship so a board can use GCT's USB4105 land pattern as drawn (docs/e2e-run-11.md, finding 2): its two Ø0.65 mm locating holes sit 0.175 mm from the GND lands, which JLCPCB's "NPTH to Track" 0.2 mm refuses with no option, while PCBWay publishes "Min width between NP holes and copper" 0.15 mm; its 0.2 mm shell-slot rings meet PCBWay's "Normal PTH pad single side width" (0.2 mm at 1 oz). *PCBWay values* (default Normal; Minimum) picks between the outer-layer table's "Normal" and "Max"/"Min" rows (and the standard table's 0.15 mm ring and drill); the Advanced PCB table's rows, graded by difficulty, keep their normal-process value under both. *Outer copper weight* offers 1, 2 and 3 oz, the weights the tolerance page lists. *Solder mask colour* follows the board's colour: green (Advanced PCB row 23, 4 mil) or any other the standard table's "Solder Mask" row lists, red, yellow, blue, white, black or purple ("variegated or black oil≥4.5mil", 0.1143 mm; read 2026-11-20). On 4 layers (1 oz inner copper) each rule also holds the Advanced table's inner-layer row where it is larger: spacing 0.127 mm (row 14, 35 µm, 5 mil) and copper to a plated or via hole 0.1778 mm (row 13, 4L, 7 mil). PCBWay publishes no outer copper-to-plated-hole limit, so on 2 layers that pair is not checked. The ESP32 example uses PCBWay 4-layer with *Minimum*, its USB pair routed at PCBWay's spacing, and passes the production check without waivers (`crates/io/tests/usb_c_part.rs`).
- **Standard.** `library/profiles/standard.json` (founder decision, 24 November 2026) is the profile a new board starts on: one simple profile for 1, 2, 4 and 6 layers at 1.6 mm and 1 oz outer copper, named for no fabricator and without options. Each rule is the strictest of the standard limits that JLCPCB (recommended values, no surcharge), PCBWay (normal values, no surcharge), OSH Park and Eurocircuits (pattern class 6) publish, over those layer counts, read 2026-11-24; its source gives the row that decides and what the others say. So a board that passes is one JLCPCB makes without a surcharge for its rules, and one the other three make in their standard services. The limits a beginner meets: 0.1524 mm (6 mil) track width and spacing (OSH Park 2 layer), 0.2 mm from a via or a pour to other copper (PCBWay), 0.4 mm copper to the board edge (Eurocircuits inner layers), 0.3 mm smallest drill (what JLCPCB and PCBWay drill without a surcharge), a 0.15 mm via ring (PCBWay; the default via is 0.3/0.6 mm) and a 0.25 mm plated pad ring (JLCPCB). A rule none of the four publishes is not checked. One value covers every layer count and mask colour, so 4-layer boards keep the 2-layer spacing and 2-layer boards the inner layers' edge clearance. Heavier outer copper is not covered and not checked: choose a fabricator's profile. Some fabricators ask more (AISLER's 2 layer HASL service: 0.2 mm tracks, a 0.2 mm via ring and a 0.3 mm plated pad ring); the profile's notes say so. A KiCad import keeps its copper whatever the profile allows; the board checks list what breaks it. `crates/io/tests/standard_profile.rs` holds every limit against the shipped JLCPCB and PCBWay profiles.
- **Thermal spoke angle by pad shape** (founder decision, 16 November 2026). Both shipped profiles set `thermal_angle` 0° (spokes along the pad's axes) and `thermal_angle_round` 45° (diagonal spokes); both are the profile author's choice, not JLCPCB limits. `thermal_angle` applies to every pad that is not round (rectangles, rounded rectangles, obrounds and custom outlines), `thermal_angle_round` to round pads and to vias. Common practice does the same, and so does the KiCad import for imported round pads. The reason: on rectangular fine-pitch lands (SOT-23-5, 0.95 mm pitch), all four 45° spokes end in a neighbour's clearance and are removed, so the pin never joins the pour. Spokes at 0° and 90° cross the row into the pour (`a_sot_23_5_middle_pin_joins_the_pour_with_spokes_along_its_axes`). The fill's code only decides which of the two values applies to a pad: the angles themselves are profile data.
- **Rules the profiles hold now.** The legend text stroke is `silk_text_stroke_share` of the text height and never under `silk_line_width_min` (it was a fixed 1/7 with a 0.1 mm floor). The via, route and pair tools start tented as `tent_vias` says. A via's drill is held to `drill_min`, not a fixed 0.1 mm floor (6 mm stays the document's pad bound). The coupled-gap tolerance is the pair class's `pair_gap_tolerance`, else the profile's `pair_gap_tolerance_share` of the gap and at least its `pair_gap_tolerance` (the former fixed 10 % and 0.02 mm, now the profile author's choice); the tightest pair gap is the track clearance (the 0.05 mm floor is gone); the "too close" band of three pair gaps is a cited constant (`layout::length::TOO_CLOSE_GAPS`).
- **Three hole kinds.** The clearance matrix pairs eight objects (36 rules): track, pad, via, fill, board edge, `via_hole`, `pth_hole` and `npth_hole`. A via's drill is `via_hole`; a plated pad or mounting hole (pad vias included) is `pth_hole`; an unplated pad or mounting hole is `npth_hole`. The via, mounting-hole and pad-hole checks and fills each read their hole's kind. The JLCPCB examples hold copper to a plated hole at the recommended 0.35 mm ("PTH to Track": "0.35mm is recommended, minimum 0.28mm"; on 4 layers this is also above "Inner layer PTH pad hole to copper clearance": 0.3mm), copper to an unplated hole at "NPTH to Track" 0.2 mm, and plated hole spacing at "Pad Hole-to-Hole Spacing" 0.45 mm. JLCPCB publishes no unplated hole-to-hole, unplated-to-via or unplated-to-plated row; by founder decision (12 November 2026) the examples read "Pad Hole-to-Hole Spacing" 0.45 mm as covering unplated pad holes too, and each of those rules says it is that reading. It publishes no hole-to-edge row, so those pairs are 0, not checked. The NPTH pad annular ring (`npth_annular_ring_min`) is "NPTH pad annular ring": "≧0.45mm". The version 1 to 2 converter (`sparksmith convert`) gives a profile without `npth_hole` rules its via-hole values, noted in each rule's source, and an unchecked (0) NPTH pad annular ring, and copies each override of a `via_hole` pair to its `npth_hole` twin.
- **One physical inventory** (`layout/physical.rs`). What is checked is what is plotted and drilled: `physical::lands` is every pad with copper, with or without a net (an unconnected pin, a fiducial, a mechanical tab), and the washer of every plated mounting hole; `physical::holes` is every drill and routed slot (vias, plated and unplated pad holes and slots, pad-owned vias, mounting holes, plated board slots). The clearance check, the router's obstacles, a routing edit's final check, the drill rules, the fill check, the board plan (washers as rings on every layer) and the fabrication output (copper lands and both drill files) read them. Copper of a net near a land without one is a `board.clearance` finding: a track across a fiducial would join it to the net. Pads of one unconnected terminal are one conductor; two unnetted, terminal-less lands of one placed part are the footprint's business. `board.track_width`: every existing track keeps its net's minimum width (its class's, else the profile's), so raising the minimum, assigning a class or changing profiles finds tracks routed before. `board.drill_size` (`board.via_drill_size` for vias): every hole and slot width keeps `drill_min`, the smallest tool the profile drills. A routing edit (`layout.route_apply`, a route step) is checked at commit against the obstacles, holes and keepouts the router plans against; board edge clearance stays a finding. A pad's inherited mask opening is the board's effective `mask.expansion` (`PlacedPad::mask_expansion`), in the Gerber mask, the legend check and the 3D view alike; the footprint default applies only in the footprint editor. The read-back oracle (`fabrication/tests/inventory.rs`) parses the written files and checks every plotted conductor and drill against the inventory, on a board with one deliberate violation of each kind, each of which must block production.
- **Pad hole checks** (`layout/pad_hole.rs`). `board.pth_annular_ring`: every plated pad hole (slots and pad vias included) leaves at least `pth_annular_ring_min` of copper to its pad's outline (one outline on every layer the pad has copper on), and every plated mounting hole as much to its ring; a round hole is measured exactly, a slot at its outline's vertices (exact on convex lands). `board.pad_hole_clearance`: a pad hole passes through every layer, so every track, pad and via within its kind's clearance is reported, except copper the copper graph joins to the hole's own pad; same-net copper that does not reach the pad is measured. `board.pad_hole_spacing`: a pad hole against every other pad hole, via drill, mounting hole and plated board slot by the hole-kind pair, whatever the nets. `board.hole_spacing` (`layout/via.rs`): each hole of the board shape (mounting holes and plated board slots) against every other one and every via drill. With `board.via_hole_spacing` (via to via) every pair of drilled feature owners is measured once (`every_pair_of_drilled_feature_owners_keeps_the_hole_spacing`). `board.edge_clearance`: every via drill, mounting hole and pad hole (a bare NPTH included, pad vias too) keeps its hole kind's board-edge clearance inside the board; one past the edge or in a cutout says so. A plated board slot is itself an edge of the board shape. Fills keep these clearances when the engine computes them (a plated board slot the larger of the edge and plated hole rules); stored fill copper short of one, via drills included, or a hole through it, is a `fill.clearance`. A net tie's bridge is measured against every hole but the plated ones of the nets it joins. `board.npth_annular_ring`: an unplated hole in a pad with copper leaves at least `npth_annular_ring_min` of copper (a bare unplated hole has none and is not measured). Via rings keep `board.via_annular_ring` (`layout/via.rs`). A waived production finding is printed in the fabrication drawing notes with its reason, asking the fabricator to confirm it in DFM review. Every hole is its own object in findings and waivers: a mounting hole, cutout or slot by its board feature id (`ObjectRef::BoardFeature`), a via-in-pad hole by its pad and index (`ObjectRef::PadVia`), so a waiver of one undersized hole never accepts another; a side's fiducial count names its side (`ObjectRef::BoardSide`).
- **Mask webs of the assembled board** (`layout/mask_web.rs`, `board.mask_web`, a warning as the footprint lint's is). Two openings on one side whose web, the copper gap less both openings' effective expansions, is under `mask_web_min`: between pads of two placed parts, and within one part where the board's mask expansion (not the footprint's own defaults, which the footprint lint measures) narrows the web. Openings of touching copper are one opening. Via openings are not measured. The ESP32 example waives its two J1 locating-peg findings (0.175 and 0.177 mm to the A1B12 and B1A12 GND lands, under 0.2 mm), which follow the GCT USB4105 drawing rev B4.
- **Unclear ranges** (`rules/profile.rs`, `Unclear`; team lead, 24 November 2026). Where a fabricator's own sources give different limits, a rule holds the strictest, which every source allows, and `"unclear": {"to": …, "source": "…"}` the loosest, with the sources quoted. A value up to the limit is made, one past `to` is not, and what lies between (`to` itself too) is not stated: the finding can be waived, only with a reason, and the waiver holds for that profile and those vias. Any length, area or ratio limit, and any case of one, can have it; it must lie past the limit. An override is the project's own limit and leaves nothing unclear. The filled hole sizes are told as `board.drill_not_stated`, other rules under their own code; `PreflightItem::not_stated` and the Issues row quote the sources (`requirement::not_stated`).
- **Filled vias** (`layout/via_fill.rs`, `rules/drills.rs`). A via's `fill` is `none` or `capped` (filled and plated over, IPC-4761 type VII), a setting of the one via (`layout.via_set`, the Via, Via tool and Route cards). A profile's `drill_rules` say which fills of a through drill the fabricator makes, each with its source; a profile without them makes open vias only. The hole sizes are rules like any other (`capped_drill_min`, `capped_drill_max`, left out where none is published). JLCPCB fills 0.2 to 0.5 mm by every page read; 0.15 to 0.2 and 0.5 to 0.55 mm are unclear. `board.drill_not_made` (error, never waivable) tells a fill or size the profile does not make; `board.drill_not_stated` (error, waived only with a reason) one the fabricator offers without a usable statement; `board.via_in_pad_open` (warning) an open hole under a paste opening; `board.via_fill_told` (warning) filled and open vias of one size where the fabricator is told by size (`order.told_by_size`). `charges` hold the published charges with their conditions, for the order notes.
- **Fabrication outputs.** The fabrication drawing states the nominal thickness over the outer copper with solder mask and legend excluded, and lists the mask rows at the stackup's mask thickness; the job file gives each solder mask its thickness.
- **Land estimates.** The land estimators (`library::samples`, `package_form::tht`, the footprint templates) read the board's profile (`tht_drill_clearance`, `tht_land_extra`, `tht_land_gap`, `gull_wing_toe_shift`, …); a board without a profile refuses to estimate lands. Still to do: the no-lead land gap from the mask-expansion constant (W4) and the inline header and no-lead land margins (N4).
- **Impedance tolerance.** A net class's impedance target sets routed widths; routed impedance is checked against the class's own `impedance_tolerance`, else the user's Settings › Rules › Impedance tolerance (`UserSettings::impedance_tolerance`, per user). Until the user sets one, Settings holds the shipped value in `library/defaults/settings.json` (10 %, with its source); the code holds none. Every host sets the same value on its engine (`Engine::set_check_settings`): the desktop from its settings, the CLI and its MCP and stdio sessions from the same settings file and shipped defaults (`sparksmith_io::settings::configure_from_env`), so `project.issues`, the production check and exports agree. With neither value (a host whose settings or shipped defaults cannot be read, and the app or CLI says why), routed copper with a target is reported `impedance.no_tolerance` ("USB_D impedance is not checked: set a tolerance in Settings"), never checked against a guess. The Net classes card's empty Tolerance field shows the Settings value it takes.

## Fabricators' stackups

A fabricator's own stackup is a versioned JSON file, `{"format": 1, "fab_stackup": {…}}`, in the shipped library's `stackups/<fabricator>/<id>.json` (`layout::fab_stackup`, loaded by `sparksmith_io::fab_stackups`). The program names no fabricator. A file that does not read is an error naming the file and the field; none is skipped.

- **What a file holds.** Every layer as published, top to bottom, each with the row it was read from; the file's source (publisher, document, address, date); the thickness option it is listed under, the thicknesses the fabricator states and the layers' own sum, with their differences; where its sources give other values (`disagreements`). The loader checks the sums, the mirror flag, every range and every glass style against the layers.
- **What a board takes** (`FabStackup::stackup`). Dielectrics as pressed, where the fabricator lists both thicknesses: the board is the pressed one. Inner foils as listed. Outer foils at the finished weight the fabricator states, 35 µm an ounce; a listed base foil that differs is named. The solder mask thicknesses, where stated. What the source does not give (mask and legend sides, hole wall, Dk estimates) stays the board's.
- **Several plies between two foils** are one dielectric. It takes the Dk its plies agree on. When they state several, it takes their average by thickness, by the rule the impedance model uses between a trace and its plane (one function, `model::weighted_dk`). The layer keeps the sheets (`Dielectric::sheets`), so the picker, the Stackup dialog and MCP say that the Dk is calculated and from what. Entering a Dk or a thickness the sheets no longer give drops them. A core without a named glass has the glass `unspecified`: no estimate, no weave in 3D.
- **Taking one** (`fab_stackup::pick`) is one `layout.edit_stackup`, one undo step. Copper layers keep their place from the top, the bottom stays the bottom and plane marks stay with their layers. Every change is named before: layers, foils, dielectrics, thickness, mask. Copper on a layer the stackup lacks refuses the edit until `moves` says where it goes; vias keep their span with their layers. A net class's `layers` are never rewritten: a class that names a moved or lost layer is told (`board.class_layer`).
- **Conflicts** are said before it is taken: what refuses the edit (copper left, an outer copper weight the profile does not order), what the fab profile says of the board then (its copper layer counts, a choice's thickness or finish), and a stackup of another maker or not listed for the profile.
- **The list** shows the board's copper layers and the maker of its fab profile. A profile that names no maker, as Standard, lists every maker, each named.
- **Desktop.** Stackup… › Choose… lists them by layers, thickness and maker, with the stack to scale, the values, the sources and the changes. Use this stackup stages it in the dialog's draft; OK applies it. Section shows the board's stack with its vias as barrels (`pcb_editor/stack_section.rs`). The table edits any stackup by hand as before.
- **CLI and MCP.** `layout.stackups` lists them, or gives one in full with what taking it changes; `layout.use_stackup {stackup, moves?}` takes one; the list names the one the board's layers were picked from (`picked`). `sparksmith stackup list [FILE.sparksmith]` and `stackup show ID [FILE.sparksmith]` print them.
- **The shipped ones** were read on 2026-11-24: 110 of JLCPCB (2, 4 and 6 layers; 0.8, 1.0, 1.2 and 1.6 mm; 1 oz outer, 0.5 oz inner) from its impedance calculator's data, and 12 of PCBWay (4 layers, 1 oz) from its laminated structure table. Read the fabricator's page again before ordering.
- **The name.** The board's stackup keeps the id and name of the one it was picked from (`Stackup::picked`), with a digest of its layers. It counts only while the layers (foil thicknesses, dielectrics' material, thickness, glass and Dk) are the ones picked: any edit of a layer drops it, a fab profile's copper weight that changes the foils too, and undo brings it back. Plane marks, mask, legend and hole wall are not layers. It is shown in the Stackup dialog and written to the order notes (`Stackup: NAME (id)`), the notes of the job file's dielectrics and the fabrication drawing's notes; the read-back compares all three.
- **Limits.** The name says which published stackup the layers are, as read on its date. Two pairs of shipped JLCPCB stackups have the same layers under two names; the list marks both as the board's layers and the picked one as the board's.

## Net classes

- **Core** (`rules/netclass.rs`):
  - Each class has a track width, a minimum width, a clearance, a fill clearance, a via drill and diameter, and a fill connection. Its pair width and gap, impedance targets and pair limits are in [high-speed routing](high-speed-routing.md).
  - A class's fill clearance replaces its clearance in any pair with a fill, whichever side the class is on; unset, the clearance applies to fills too. It can be lower or higher than the clearance. The rule's fill clearances and class-to-class clearances still set the floor, and tracks and pads never read it (`fill_clearance_applies_to_fills_only`, `a_fill_clearance_leaves_a_tight_route_routable`).
  - `vias` (`spans`, `max`) says which vias a net of the class may have: unset any, an empty `spans` none, `max` the most a net may have. `layers` lists the copper layers its tracks may use.
  - A class's values are checked against each other.
  - An explicit assignment beats the first matching name pattern (`*`/`?`). Nothing else assigns a class.
  - Assignments follow nets through `nets::reconcile`:
    - A survivor without its own class inherits the merged-away nets' class when they agree.
    - A net that splits off takes its origin's class.
    - Nets that are gone drop their assignment.
  - `net_class.list` reports every class with its resolved values and every net with its class and basis.
- **Vias and layers.** Every edit that adds a via or puts a track on another layer is refused when the class does not allow it, naming the class (`layout/via_class.rs`); the Route and pair tools refuse the layer change and stay on their layer. Copper that is already there (an import, a later class edit) stays and is told by `board.via_class`: each via past the number by its place in the board's order, and each layer's tracks of a net. A stackup edit never changes a class's `layers`: `board.class_layer` (warning) tells a class that names a layer an edit moved (`moved_layers`, kept until the class's layers are set again or it is confirmed empty) or that the board does not have.
- **Routing.** `layout.route`, `route_apply`, `track_set` and `route_layer_change` refuse widths below the net's class minimum or the rule minimum. `layout::route_width` and `layout::class_via` give the class defaults. Clearance checks use the class and class-pair values, and so does a library update's impact preview (`layout::track_pad_clearance_conflict` and `via_pad_clearance_conflict` take `limits::BoardRules`; `the_impact_plan_reads_net_class_clearances`).
- **Desktop.**
  - The Route tool starts at the routed net's class width; a typed width stays for that net. The Via tool and layer changes place the class's via. While routing, W and D step through the presets of the rules: the net's own values, the defaults and every class's values, never below the minimums (`layout::route_widths`, `layout::via_sizes`, `layout::via_size_fits`).
  - The Track, Via and schematic Net cards have a Class row.
  - The Net classes card (`pcb_editor/net_classes.rs`) shows classes, values, class-to-class clearances, members and name patterns. It opens from the Board card's Net classes row; it and the Design rules panel replace each other in the subject slot.

## Copper fills and keepouts

- **Region.** A fill's `region` is stored, never inferred from its coordinates. `drawn` (the default) keeps its own outline at fixed board coordinates. `board` follows the board: after every operation `layout::fill::follow_board` gives it the solved board outline, so a board parameter or shape edit (`width`, `height`, `corner_r`, a sketch edit) moves its region at once, and its copper is stale until the next refill (the desktop's background refill, or `fill.refill`). A `fill.add` with `region: board` needs no outline. Editing a board-following fill's outline is refused (`fill.follows_board`) until it is made a drawn fill, which keeps the outline it has; a part dimension on one is refused too. The Fill card's Region row switches between Board outline and Drawn, and a board-following fill has no outline handles (`a_board_following_fill_grows_with_the_board_width`).
- **Computation** (`layout/fill.rs`, `layout/fill/compute.rs`) is a pure, deterministic function of the project. It uses `i_overlay` (MIT OR Apache-2.0; see [attribution](../ATTRIBUTION.md)). For one fill:
  1. The fill's outline is clipped to the board outline, shrunk by the fill-to-board-edge clearance.
  2. These are subtracted at the effective rule and net-class clearances: cutouts and slots, mounting holes, keepouts, other-net copper and higher-priority fills.
  3. Same-net pads and vias connect solid or through thermal reliefs (spoke count, width, gap and angle). The rule's angle depends on the pad's shape: `thermal_angle_round` for round pads and vias, when the profile or an override sets it, and `thermal_angle` for every other pad ([thermal spoke angle by pad shape](#fab-profile-files)). A fill's own relief setting gives one angle to all its pads and vias, and a part's or pad's spoke angle override wins over both (`round_pads_and_vias_take_the_round_pad_spoke_angle`). A spoke must cross its relief gap to copper of the net (the fill's copper beyond its end or beside it, or another joined pad); one whose gap opens onto nothing it can join is removed. The spoke's copper is what stays connected to its pad anywhere across its width, so a spoke that a neighbour's clearance narrows past the gap still joins through the rest of its width (`a_spoke_narrowed_by_a_neighbours_clearance_still_joins_the_pour`). The fill records how many spokes each pad or via lost, and Issues tells the person with one information row per pad or via (`fill.spokes_removed`, naming the pad and the fill; it blocks nothing and can be waived). The rule and the notice were approved by the founder on 15 November 2026 ([copper graph Q9](copper-graph.md#fill-policy-question-q9-decided)). The style is set per fill for surface pads, through-hole pads and vias (`settings.connections`), then by net class, then by rule. A placed part may override how fills join its pads, and each pad may override its part, field by field: connection, spoke width, spoke angle, relief gap and clearance (the gap fill copper keeps to a pad it does not join, in place of the fill's own; the clearance rules still set the floor). These overrides win over the fill's settings. They are stored on the placement (`fill_override`, `pad_fill_overrides`), set with `fill.set_pad_override` (empty settings remove one) and edited in the Placement card's Fill connection section, whose "Applies to" row picks the whole part or one pad (`part_and_pad_overrides_change_how_the_fill_joins_a_pad`). An override is part of each nearby fill's inputs key, so changing one makes those fills stale. The copper graph still decides what the resulting copper joins.
  4. A minimum-width opening drops slivers.
  5. Hatching and island removal are options. An island stays when it joins a pad, via or track of the fill's net on its layer, by the copper graph's one joining rule ([copper graph](copper-graph.md)), itself or through islands of the net's other fills on the layer, whatever their priorities. Fills that join only each other go. Fills whose copper depends on each other's are settled together, so the order they are filled in never shows; a fill's key takes in the inputs of every fill its copper reads, and no computed copper, so storing one makes no other stale.
- **Results.** The copper (`FilledCopper`: its islands and the count removed) is stored on the fill with the key of its inputs. What the islands join is not stored.
  - `inputs_key` covers only the objects within the fill's reach, so an edit elsewhere leaves the fill fresh.
  - `fill.store` refuses copper whose key is stale; `fill.store_all` stores several fills as one undo step and refuses the whole batch when any key is stale.
  - The copper graph joins a fresh fill's islands to the pads, vias and tracks they touch and to the islands of the net's other fresh fills on the layer, for board connectivity and airwires. Stale copper joins nothing, so an airwire shows as soon as a joined pad or via moves off the pour.
  - Fill copper is bounded per fill (2^20 vertices) and per project (2^23).
- **Checks:** every fill's stored copper is audited against the board it will be plotted on, whatever its key says: a current key says which board a worker computed for, not that the regions it returned are right (`layout/fill/checks.rs`). The geometry is prepared once per check run (every land, hole, via and track in one bounds grid, each fill's regions indexed once).
  - `fill.clearance`: fresh copper keeps the clearance rule of each pair from every other-net land (pads with or without a net, washers), via and track on its layer, every hole it does not own (a plated hole of its own net is drilled out of it; a via's drill is measured as well as its copper, on every layer it passes), every net tie bridge and every other-net fill on its layer. Copper also keeps the fill's own clearance, or the pad's fill override in its place, as the fill computation keeps them. An object short of two rules (a via's copper and its drill) is one finding that states both. The gap is measured edge to edge and named ("fill Return is 0.025 mm from a track on N1; needs 0.2 mm …"); a gap short of the rule by no more than the fill chord and 1 µm (`AUDIT_SLACK_MM`, the fill computation's own flattening) passes. Stale copper is reported only where it overlaps (its refill cuts the gaps the rules now ask for), so a profile switch does not list every gap; it carries its `fill.stale`. That cannot be waived.
  - `fill.overlap`: copper that touches copper or the plated hole of another net, fresh or stale. Like `board.overlap` (lands, vias and tracks of two nets that touch) it is a short and cannot be waived.
  - `fill.board_edge`: copper outside the board outline (named with the stray copper's lowest-left corner: "at (90, 80) mm") or in a cutout or slot, and fresh copper closer to an edge than the fill-to-board-edge rule.
  - `keepout.fill`: copper in a keepout that forbids fills on its layer. Overlap is an area: a fill drawn up to a keepout, cutout or (with no rule) another outline meets it without overlapping.
  - The audit measures every object; it lists at most 256 rows per fill, and past them one `fill.clearance_unlisted` counts the rest. That row is an error that may not be waived, since a waiver could not say which copper it accepts.
  - `fill.empty`, `fill.island_unconnected` (an island of fresh copper that the copper graph joins to no pad, via or track, kept because the fill keeps every island), `fill.net_missing`, `fill.stale` and `keepout.track`/`via`/`pad`.
- **Background refill.** The desktop fill worker (`apps/sparksmith/src/fill_worker.rs`) computes stale fills off the UI thread with `FillCache` and `compute_stale`. It stores them with `Engine::store_fills`, which adds no undo step and computes the keys of the stored fills only.
  - A store raises the revision but is no one's change (`Engine::content_revision`, `Engine::still_at`): an edit, undo, redo or update prepared before it still runs, reviews stay current, and nothing typed or dragged is dropped. Only what shows or exports the copper itself (a Full interface publish, a held native export) is renewed.
  - A fill's key holds the solved outline, the cutouts and the mounting holes, not the sketch behind them: a sketch edit that moves none of these leaves the fills fresh.
  - An explicit refill (the Fill card's and Layout's Refill) also runs on the worker. The app commits its copper as one undoable `fill.store_all` and says "Refilling in the background" meanwhile; a refill whose revision moved on is computed again. The CLI and MCP keep the synchronous `fill.refill`.
- **Measured** (1 November 2026, macOS arm64, release build): one fill of a 200 × 200 mm plane over 10,000 through vias took 1.40 s, and its inputs key 2.1 ms (`a_large_board_fills_in_seconds`, which prints both).
- **PCB 2D** (`fill_paint.rs`, `fill_tool.rs`, `fill_card.rs`):
  - Fill copper is drawn under its layer's tracks: solid, hatched or outlines only, set in the view popover's Fills row. On the active layer it is the layer's opaque colour; on another layer it is lighter than that layer's tracks (a translucent tint with its outline), so a pour never hides the active layer ([PCB realism](pcb-realism.md#pcb-2d-appssparksmith)). It is triangulated once per copper with `spade` and cached.
  - Keepouts are drawn as hatched outlines over all copper, labelled with the layers they apply to, in every layer focus mode.
  - Unfilled fills show as dashed outlines.
  - The selected fill's outline has vertex and midpoint handles. Each release is one `fill.edit`.
  - The Fill tool draws outlines with lines and three-point arcs. The Fill card edits net, layer, priority and settings, with Refill and Delete in its footer.
- **PCB 3D** (`crates/solidcraft-integration/src/project/fill.rs`):
  - Each region of fill copper is a saved `FillCopper` body, one component per fill, on its layer and as thick as its foil. Its loops are simplified to 10 µm (`MODEL_CHORD_MM`, Douglas–Peucker) first; the document's 5 µm copper gives a pour thousands of faces. The regions go into one sketch command each (`Native::batched_body`), and the fill components are joined to the board with every other part at the end of the build.
  - An inner fill lies in its own foil level of the laminate (`fill::foil_level`), as inner tracks and via rings do in the stacked-slab laminate ([PCB realism](pcb-realism.md#saved-physical-bodies)): the fill's regions, united with every track, via ring and hole that overlaps them, are holes of that level's slab, so the saved bodies do not interfere and the laminate's mass is physical, with no Boolean. A round ring joins that union as a circumscribed 64-gon, so the laminate stays clear of its exact circle; copper that does not touch the fill keeps its exact circle. Laminate left in a clearance (round another net's via) is a body of its own, `Substrate 2 (2)`, … (`an_inner_fill_lies_in_its_own_foil_level`).
  - Outer fills get a display-only mask cap.
  - (Before stage A4, which removed the in-place update of the native board.) A fill edit updated the model in place (`fill_edits_update_the_filled_board_in_place`): the fill bodies' sketches, and an inner fill's foil slab, are redrawn. An extrusion whose profile pick named redrawn curves (a region with holes, a slab in pieces) is rebuilt from its command (`timeline.redefine`), which picks the redrawn profiles as a fresh build does. An edit that leaves a slab in other pieces (a drill moved through an inner fill splitting or joining laminate) still updates in place: the pieces as evaluated get the laminate's kind, look and saved identity, as in a fresh build.
  - Measured (2 November 2026, macOS arm64, `ci` profile, load average about 5): the shipped showcase exports (`sparksmith export`) in 2.3 s, against 8.3 s for this batch before the merge with the via-scaling work; the filled `Engine::showcase` builds in 1.16 s (`build_timings`; 0.85 s unfilled on the via-scaling branch). `the_showcase_fills_cost_little_of_the_build` keeps the filled showcase within 1.25× of the same board unfilled.
- **Showcase.** `Engine::showcase` has a bottom GND pour, an inner GND plane and ten stitching vias and refills them. The shipped file (`sparksmith showcase`, `Engine::showcase_hosted` with the sketch evaluators) adds a Power class over GND and VCC (0.5 mm tracks, 0.25 mm minimum, 0.4/0.8 mm vias, the profile's clearance), a top GND pour (thermals to the header and vias, solid to surface pads), and a sketched board: 2 mm rounded corners through `corner_r`, a 3.5 mm round cutout, a 1 mm milled slot and J1 held to the left edge at `height / 2 - 1 mm`. Its board checks are clean (`the_shipped_showcase_has_its_shape_classes_and_edge_held_header`).

## Etch hazards: acute copper angles and unfilled slivers

Two warnings of the board checks (`layout/etch.rs`, run by `layout::checks_with`, so by Issues and the production check). Both rules are in the design rules (`DesignRules::etch`, `EtchRules`), edited in the Rules panel (Copper › Min copper angle, Fills › Min sliver width) and through `rules.set_override` / `rules.clear_override` on `copper_angle_min` and `sliver_width_min`.

- **Defaults: unset (0, "Not checked").** We found no IPC figure or major fabricator's DFM number we could cite for either. A search (9 November 2026) turned up only vendor blog posts, which disagree with each other (some call any angle under 90° a risk, others accept 90°) and give no sliver width for bare gaps. So both ship unset: a min angle or width of 0 has nothing under it. Enter your fabricator's numbers to check them. Angles take 0–180°, widths 0–25 mm.
- **Check-only.** Fills do not read them: `ProjectRules::without_checks` leaves them out of the fill inputs key, so setting either leaves every fill fresh (`etch_rules_leave_fills_fresh`). Unset, they are left out of the saved rules.
- **`board.acute_copper`**: a bare wedge between joined copper edges on one layer narrower than the min copper angle. The copper graph finds them (`CopperGraph::wedges`, `layout/connectivity/wedges.rs`), from its joints only, on straight edges:
  - track to track where the centre lines meet (corner, T, crossing): the wedge between consecutive centre-line rays, at the apex where the facing sides cross. A wedge whose apex lies past a track's round end is not reported.
  - track to pad where a track side crosses a straight pad edge (rectangle sides, the straight parts of rounded rectangles and oblongs, a custom outline's line segments). Round pad edges and vias are not measured.
  - track to fill where a track side crosses an edge of a fresh fill island of its net, on the stored copper. The fill edge's direction is its chord over the track's half-width from the crossing: exact on a straight edge, and not one short chord's direction on a flattened curve. A notch shallower than that half-width is not reported.
  - A wedge that other copper of the net fills (a pad at the corner, a pour over both tracks) is no wedge. One finding per pair of objects, at its sharpest wedge.
- **`board.copper_sliver`**: inside a fresh fill, a bare gap narrower than the min sliver width between two pieces of copper of nets other than the fill's (tracks, vias, pads), or between such copper and the board edge, that the fill did not flow into. The gap is measured between the outlines the copper graph and the clearance check use, at its narrowest point; it is a sliver when that point is inside the fill's outline and the board, outside keepouts that forbid fills, and no copper (the fill's own, another fill's, any track, pad or via) crosses it. Two pads of one placed part are left out: the footprint sets their gap, as the clearance check treats them. At most 1,000 findings, then `board.check_limit`.
  - Fill slivers: fill compute already removes solid copper narrower than the fill's min width (an opening, `fill_slivers_are_removed_and_thin_hatches_are_reported`). A hatched fill whose hatch width is under its min fill width is reported as `board.copper_sliver` on the fill, whatever the sliver rule.
- Each finding names its objects (tracks, pad, fill, the board for an edge) and gives the location in its message, for example "Copper angle 30° < 90°: a track on VCC / a track on VCC on Top at (10.467, 10.125) mm (project override: min copper angle)" or "Unfilled gap 0.4 mm < 0.5 mm: a track on VCC / a track on GND in EN fill on Bottom at (20, 15.325) mm (…)".
- **Measured** (9 November 2026, macOS arm64, `test` profile: core at opt-level 1): on the 10,000-via benchmark board with a full-board pour and both rules set, the etch checks take 10.6 ms (angles 4.1 ms, slivers 6.9 ms, of which finding the fresh fills is 3.1 ms); unset, they cost nothing (`the_check_is_cheap_on_ten_thousand_vias` prints these).
- **The ESP32 example** keeps both unset, so its board and production checks have no etch finding (`crates/io/tests/esp32_etch.rs`). Under a 90° angle and its fills' flow limit (twice its fill clearance and its minimum fill width: 0.502 mm on its PCBWay rules) it has 26 acute wedges and 96 slivers; the test prints them.

## Fiducials

A fiducial is a pad of kind fiducial: bare copper that lands no terminal and takes no paste. The `fiducial` generator makes the whole part ([generators](../generators/README.md)): the dot, its mask opening, a clear area that is the footprint's courtyard and a copper keep-out on the dot's own outer layer (`Keepout.side`, stored as `KeepoutScope::ComponentSide`, or `OppositeSide` for the far dot of a both-sides fiducial), no silkscreen, no terminals, and no body (`Model::NoBody`, stored as `PackageModel::NoBody`): the board plan draws the land, so the 3D view and the exports add no copper of their own. Its presets come from JLCPCB's and PCBWay's assembly guidelines, cited in `generators/fiducial/presets.json`.

The checks (`layout/fiducial.rs`, warnings, run with the board checks) take their limits from the profile's assembly rules, `fiducial_count_min` and `fiducials_asymmetric` (`DesignRules::assembly`). Both are optional in a profile file (a fabricator that does not assemble publishes none, and then nothing is checked); the shipped profiles set them, each quoting its source:

- **`board.fiducials_too_few`**: a side carrying surface-mount lands of a part the active variant fits has fewer fiducials than `fiducial_count_min` ("The top side has 2 fiducials for its surface-mount parts; needs 3 (JLCPCB 2-layer: min fiducials per assembled side)"). JLCPCB: 3 recommended, 2 under *Absolute minimum*; PCBWay and Standard: 3.
- **`board.fiducials_symmetric`**: with `fiducials_asymmetric`, a side's two or more fiducials map onto themselves under a half turn about the centre of the board outline's box, each within 1 µm (the fabrication files' resolution), so a board turned round looks the same to the camera.
- **`board.fiducial_silk`**: silkscreen (a drawing or text, any part's) reaches into a fiducial's clear area on its side. The clear area is the keep-out on the dot's layer that holds its centre, else its mask opening.
- **`board.fiducial_copper`** (an error): a track or via reaches into the clear area of a fiducial that carries no keep-out of its own (a footprint made elsewhere), its mask opening. Where the fiducial has a keep-out, copper in it is a keep-out finding (`keepout.track`, `keepout.via`, also errors; fills stay out of it). Another part in the clear area is a courtyard finding (`board.courtyard_overlap`).
- Fiducials are found from the physical pad list the fabrication films draw (`layout::placed_pads`), not from the netted pads the copper graph uses, so an unnetted fiducial is checked as the Gerber writes it; its opening is `PlacedPad::mask_expansion`, the one reading the mask film shares.

No check for local fiducials of fine-pitch parts yet: JLCPCB's blog places them for 0.5 mm pitch or less, "typically" two diagonally across the land pattern, which names no distance a check could hold a fiducial to.

## Board shape, cutouts and edge-relative placement

- **Copper off the board.** A document may hold tracks and vias off its board, within the working area: an import's copper is never dropped. The board check tells them (`board.outside_outline`). No edit puts copper there: routing refuses it, and an edit that leaves a track or via off the board's box that was on it before is refused (`layout::copper_stays`); what was off it already stays in no one's way. The finding blocks production; accepted, the files hold the copper, drills and legend exactly where the design has them, as the read-back checks over whole files, and the profile and the job file's size stay the outline's (`fabrication/tests/off_board.rs`). A waiver of it holds however far the copper is off: it has no measured value.
- **An import without an outline** (no Edge.Cuts, or drawings that do not close) leaves the board's sketch without one: `board.shape_invalid` or `board.shape_open`, which block production and are never waived; `fabrication::generate` refuses such a board itself (`fabrication.outline_invalid`), so no caller gets files of the last valid shape. The last valid shape, which the views show, is then a provisional rectangle round everything on the board with a 2 mm margin; no line of it is in the sketch, so closing the outline is drawing it. Only a host without a sketch engine keeps that rectangle as the board's (`OutlineProvisional`); the desktop app, the CLI and MCP all have one.

- **Model** (`model/board.rs`, `layout/outline.rs`):
  - `BoardShape` is a `Rectangle` (from `board_size`) or a `Sketch(BoardSketch)`. A sketched board keeps `board_size` at its solved bounding box.
  - `Project::board()` returns the solved shape: the outer outline, cutouts, slots, mounting holes and named edges. For a rectangle, the edges are bottom/right/top/left.
- **Sketch** (`crates/solidcraft-integration/src/board.rs`). `SketchBoardEvaluator` runs on the footprint sketch machinery: canonical sketch check, parameters in Solidcraft's expression language, bound dimensions and the solver.
  - `board.start_sketch` turns the rectangle into a fully constrained sketch driven by `width` and `height`.
  - `board.edit` applies sketch edits, parameters, outline/cutout/slot/mounting-hole roles, edge names, real tangent fillets and milled slots as one undo step. Its outcome (`board_edited`) lists the points, curves and constraints it created and kept, so a client can name them in the next edit. A fillet keeps a virtual corner, so dimensions and named edges still run corner to corner: `board.shape` reports a filleted board's `bottom` edge from (0, 0) to (w, 0) while its `outer` loop's line runs between the fillets. A part dimensioned to the edge measures to its line, so it stays put when the corner radius changes.
  - The edit is refused when the shape is unsolved, over-constrained, open or out of range.
  - A dimension that other constraints already determine is refused (`board.dimension_redundant`), naming what sets it ("‘height’ already sets this"): it would remove no freedom, and a board sketch has no driven dimensions.
  - In the window, a placed dimension is in the sketch only once its value is accepted: one `board.edit` adds it with the parameter its value defines (`name = expression`), so a refused value leaves nothing. A click within reach of the origin ties to it as to any other point, and an arc ends on the points it is clicked on.
- **Part dimensions** (`layout::dimensions`, design in [board sketch references](board-sketch-references.md) §5.2) replaced edge constraints. They are solved after every operation that touches them, on Solidcraft's sketch solver behind the board evaluator.
  - A placement, fill or keepout is held by dimensions and constraints between its origin, axes, pads, courtyard or anchors and board points and curves (or other parts). Values are numbers, board parameters or expressions over them. Parts move when board parameters change; a degree of freedom no dimension fixes keeps its value.
  - Board and part-dimension edits carry tracks, vias and differential pairs with solved placements. A board made smaller is checked against its tracks and vias where that carry left them ("2 tracks on GND and CC2 would lie outside 38 × 64 mm" names what nothing carried), so copper that follows its parts onto the smaller board is no refusal (`a_narrower_board_takes_the_copper_its_held_part_carries`). If rerouting cannot retain a connection, or the copper graph finds a lost explicit-copper connection or a new dangling track/via, the whole edit is refused with the affected net names; the document, revision and undo history stay unchanged. Successful carries remain one undo step. This guard compares copper without fills on both sides: fill-only connections still depend on the background refill and subsequent board checks.
  - A move is a solver drag: a part dimensioned to one edge slides along it. A move that cannot land is refused with the reason and the way out: "J1 is held 2 mm from the right edge; edit or delete its dimensions to move it" (`dimensions::held_message`). A locked part's move is refused as "J2 is locked; unlock it to move it". `layout::move_refusal` gives a client either text before it tries.
  - A dimension whose part, pad, anchor or board geometry is gone stops driving and is reported as `board.reference_lost`, which blocks fabrication output with no waiver. A stored sketch that no longer solves is reported as `board.shape_unsolved`.
  - A dimension can also name a face, edge or vertex of a part's part file by its persistent Solidcraft name, body and a pick point in the model frame (slice S3, [board sketch references](board-sketch-references.md) §14). The host traces it in the board plane (a face square to the board is a line, a vertical hole or boss its centre); a sloped or flat face is refused. A reference the part file no longer has is `board.reference_lost`; one found but not provably the same is `board.reference_inexact`. Both block fabrication output, and a library update lists them first in its preview.
- **3D.** Every laminate slab is extruded from the solved outline with its cutouts, slots and mounting holes as holes (no Boolean); a sketched board's slabs do not follow `board_width` and `board_depth`. The display-only mask films follow the solved outline (inset 0.03 mm) and open over every cutout, slot and mounting hole; the edge bands line the outline and each cutout and slot (`the_mask_and_edge_bands_follow_the_sketched_shape`). Fill computation and board-edge checks read the same shape.
- **Desktop** (`board_shape.rs`, `board_shape_ui.rs`, `edge_card.rs`):
  - Layout's Shape button opens the Board shape mode on the footprint editor's sketch view.
  - The tools are Line (L), Arc (A), Circle (C), Rectangle (R, with a parametric corner radius), Spline (S), Ellipse (Shift+C), Conic (Shift+A), Fillet (F), Dimension (D, bound to board parameters), Cutout (U), Slot (Shift+H), Mounting hole (H) and Name edge (E). X toggles construction geometry. Every gesture is one `board.edit`.
  - The Constrain group holds Dimension, one split button with the twelve constraints (`ShapeTool::Constrain`, each with its own registry key) and Constraints (G). Picks end in one `board.edit`. A constraint Solidcraft's `determined_by` finds already set is refused naming what sets it (`refuse_redundant_constraint`); on `board.edit` from MCP and the CLI one that holds is kept, as Solidcraft keeps it. A point of a free-form curve put on that curve, and Equal on one, are refused on every surface. In a small window the group is in the ribbon's » menu, which scrolls.
  - Constraint glyphs are drawn by `sketch_glyphs.rs`, as in the footprint sketch. They show for what the pointer is on, the selection, the picks and a conflict; Constraints shows all. A click selects one, Delete removes it or the selected dimension, and the parts dimensioned to what it held are counted (`dimensions::dimensioned_to`). A point dropped on another is joined to it in the same step.
  - Why a parameter or part dimension was refused shows under its row and is scrolled to (`ListView::error`).
  - The free-form tools follow Solidcraft's. Spline takes fit points (or control points); a click on the first point closes a fit-point spline smoothly, and Enter, a double-click on the last point, a right-click or the card's Finish ends it open; Backspace takes back a point and Esc drops it. Ellipse is the centre, the end of the major axis, then a point on it. Conic is the start, the end, then the apex, with the card's Rho (0.5 a parabola). Clicks on existing points are tied to them in the same step, so a conic or spline can close a loop with other curves. The preview is the curve drawn in a scratch sketch (`sparksmith_solidcraft::board::free_form_preview`); it never touches the document.
  - The Placement section opens with the part's state: "Free · nearest: right" with "Dimension to edge", which adds the part's distance to the nearest named edge in place; "Held 2 mm from the right edge" (with "Free part" when one dimension holds it); or "Locked in place". A dimensioned part's Dimensions section edits each value live and deletes any one, and the canvas draws its distances to named edges while it is selected. Dragging it previews where the engine lands it (`dimensions::landing`).
  - Unselected, a dimensioned part carries Solidcraft's Dimension glyph with a `dimension` rim and a locked part the Fix glyph with a `sketch_locked` rim, just outside the top-right corner of its envelope (`pcb_editor/hold_mark.rs`). Free parts carry nothing. The glyph keeps its screen size and becomes a dot of the same colour when the part is smaller on screen than the glyph.
  - The Board card shows the shape and edits the board parameters.

## Limits

- Push-and-shove was not part of this work; routing respects class widths and the rule minimums. It was built later on the seam described in [high-speed routing](high-speed-routing.md#the-push-and-shove-seam); see [push-and-shove](push-and-shove.md).
- Document validation still bounds vias by the board's bounding box (`board_size`). A via outside a sketched outline but inside its bounding box is a board-edge finding, not an invalid document.
- The Board shape mode, the Fill tool and card, the Net classes card and the Design rules panel are covered by engine and egui-frame tests (`the_host_evaluator_solves_a_cutout_gesture_on_the_engine` drives a Cutout gesture through the linked sketch engine).
- The shipped showcase's cutout and slot are drawn at coordinates, not dimensioned, so its sketch solves under-constrained; its outline is fully driven by `width`, `height` and `corner_r`. The fully dimensioned example is the [ESP32-S31 dev board](../examples/esp32-s31-devboard/README.md#board): a tab, a notch, a slot, a window and three holes, every dimension a board parameter and every part held by part dimensions (`crates/automation/tests/esp32_parametric.rs`).
- A part dimension's distance to an edge does not say which side of the edge the part is on: the parts solve takes the nearer of the two places. When a board edit moves the edge past the part in one step, that is the far side. Measured on the ESP32-S31 dev board with J3 held `(width − header_span) / 2` from the right edge: `width` 46 → 40 mm puts the right edge 0.46 mm past J3, and the solve put J3 2.54 mm outside the board (the copper on its pads could not follow, so the edit was refused with `board.carry`; 45 → 40 mm, where the edge does not pass J3, was taken). That board now measures its parts along x from the left edge, which stands on the origin.
- A slot is drawn at two points (`board.edit` `add_slot`) and then held: its cap centres are sketch points like any other, so dimensions from them to edges, a `horizontal` constraint and their distance leave it no freedom. Nothing in a sketch is held by the coordinates it was drawn at.
- `rules.preview_fab_profile` runs two issue reports on the UI thread; it has not been measured at 10,000 vias.

### Current through a tie

Set the allowed temperature rise in degrees Celsius and supply the table with
`rules.set_tie_current`. The rule stores a project-local snapshot. Its table
names the source, IPC-2152 edition and figure. Each row gives `rise_c`,
`area_mm2` and `amperes`. Sparksmith ships no IPC-2152 curves. The person
designing the board or their library supplies the data. A fab profile JSON file can carry the same table in `current_table`. The project’s supplied table takes precedence, and the project always chooses the temperature rise.

The check uses the smallest cross section across the bridge lands and the
foil thickness on the actual copper layer. At the chosen temperature rise
it uses the largest tabulated area no greater than that cross section.
The reported margin is the capacity less the instance's Rated current.
A missing table, setting or applicable row leaves the current unchecked.
A fitted 0 Ω link uses its manufacturer's Part rating.
